# Оценщик ИИ-кейсов

Инструмент для руководителя направления ИИ: по описанию бизнес-задачи считает экономику внедрения, определяет класс риска и требования ИБ, ставит кейс в общую очередь и даёт рекомендацию. Отвечает на два вопроса, которые чаще всего остаются без ответа в пилотах: «окупится ли это» и «что нужно, чтобы это было безопасно».

Принцип: **модель извлекает, правила решают.** Локальная LLM переводит свободное описание задачи в параметры и пишет резюме для руководства. Экономику, класс риска и приоритет считает прозрачный код по одинаковым для всех кейсов критериям. Поэтому любую рекомендацию можно объяснить и оспорить по цифрам.

## Что получается на выходе

Для каждого кейса:

- **Экономика:** эффект в месяц, стоимость эксплуатации (токены или GPU, подписки, сопровождение), стоимость внедрения, TCO и ROI за 36 месяцев, срок окупаемости, стоимость одной операции.
- **Риск:** класс по логике EU AI Act (минимальный, ограниченный, высокий, недопустимый) и причины.
- **Блокеры:** например, персональные данные во внешнем зарубежном сервисе.
- **Требования**, сгруппированные по функциям NIST AI RMF: Govern, Map, Measure, Manage.
- **Приоритет и рекомендация:** «Внедрять в первую очередь», «Пилот», «Пилот с контролем человека», «Подготовить данные и интеграции», «Не окупается», «Отклонить до устранения блокеров».
- **Допущения:** какие параметры не заданы и взяты по умолчанию, чтобы было видно, где оценка грубая.

Для портфеля: очередь внедрения и HTML-отчёт для руководства.

## Пример: портфель лизинговой компании

В `examples/cases` 7 типовых кейсов вымышленной лизинговой компании. Результат:

| # | Кейс | Окупаемость, мес. | Риск | Рекомендация |
|---|---|---|---|---|
| 1 | Проверка договоров поставки юристом | 1,3 | Минимальный | Внедрять в первую очередь |
| 2 | Ассистент оператора поддержки | 1,6 | Минимальный | Внедрять в первую очередь |
| 3 | Распознавание документов в лизинговой заявке | 1,6 | Минимальный | Внедрять в первую очередь |
| 4 | Агент напоминаний о просроченных платежах | 5,1 | Ограниченный | Пилот |
| 5 | Автоматическое решение по заявке малого бизнеса | 3,0 | Высокий | Пилот с контролем человека |
| 6 | Генерация текстов для рассылок маркетинга | не окупается | Минимальный | Не окупается |
| 7 | Чат-бот на сайте через зарубежный API | 1,0 | Ограниченный | Отклонить до устранения блокеров |

Последний кейс показывает, зачем нужна оценка рисков: по деньгам он самый быстрый, но передаёт персональные данные во внешний зарубежный сервис. Шестой показывает обратное: безопасный и простой кейс, который не окупает даже подписку.

## Быстрый старт

```bash
pip install -r requirements.txt

# портфель и HTML-отчёт
python -m aicase.cli portfolio examples/cases --html reports/portfolio.html

# один кейс
python -m aicase.cli assess examples/cases/01_support_assistant.yaml

# тесты
python -m pytest
```

### С локальной LLM (Ollama)

```bash
ollama pull qwen2.5:7b-instruct

# свободное описание задачи -> параметры -> оценка
python -m aicase.cli assess-text "Операторы колл-центра обрабатывают около 20 тысяч обращений в месяц и тратят по 3-4 минуты на поиск ответа в базе знаний. Хотим ассистента внутри контура, который подсказывает ответ. Данные внутренние."

# отчёт с резюме для руководства
python -m aicase.cli portfolio examples/cases --html reports/portfolio.html --summaries
```

Ответ модели проверяется по схеме (pydantic). Если проверка не прошла, модель получает текст ошибки и одну попытку исправиться. Числа, которых нет в описании, модель не придумывает: такие поля берутся по умолчанию и попадают в список допущений. Если модель недоступна, отчёт строится без резюме.

## Методика

Формулы, шкалы и правила классификации: [METHODOLOGY.md](METHODOLOGY.md). Все коэффициенты вынесены в код в явном виде и настраиваются под компанию.

## Структура

```
aicase/
  model.py      схема кейса и допущения
  economics.py  эффект, TCO, ROI, окупаемость
  risk.py       класс риска, блокеры, требования по NIST AI RMF
  scoring.py    приоритет, рекомендация, очередь
  llm.py        извлечение параметров и резюме через локальную LLM
  report.py     HTML-отчёт и вывод в консоль
  cli.py        командная строка
examples/cases/  кейсы лизинговой компании (вымышленные данные)
tests/           автотесты, включая проверку LLM-извлечения на подставной модели
```

## Ограничения

- Это инструмент первичной оценки и приоритизации, а не юридическое заключение о соответствии EU AI Act или 152-ФЗ.
- Качество экономики зависит от входных оценок (минуты экономии, доля использования). Поэтому допущения показываются явно, а после пилота оценку стоит пересчитать по фактическим данным.
- Правила классификации риска упрощены и должны быть согласованы с ИБ и юристами компании.
