# Методика оценки ИИ-кейса

## 1. Экономика (горизонт 36 месяцев)

| Показатель | Формула |
|---|---|
| Операции с ИИ в месяц | операции в месяц × доля использования |
| Сэкономлено часов в месяц | операции с ИИ × минуты экономии / 60 |
| Эффект в месяц | часы × стоимость часа сотрудника + прочий измеримый эффект |
| Токены в месяц | операции с ИИ × (входные токены × цена входа + выходные × цена выхода) / 1 000 000 |
| Эксплуатация в месяц | токены + инфраструктура и подписки (GPU, лицензии) + часы сопровождения × стоимость часа ИТ |
| Внедрение | трудозатраты × стоимость часа ИТ + разовые затраты |
| TCO за 36 мес. | внедрение + эксплуатация × 36 |
| ROI за 36 мес. | (эффект × 36 − TCO) / TCO |
| Окупаемость, мес. | внедрение / (эффект − эксплуатация), если разница положительна |
| Стоимость операции | эксплуатация в месяц / операции с ИИ |

Для локальной модели цена токенов равна нулю, а затраты отражаются в строке «инфраструктура» (аренда или амортизация GPU).

## 2. Класс риска

Логика EU AI Act, адаптированная под внутреннюю политику:

1. **Недопустимый:** запрещённые практики (манипуляция, социальный скоринг). Кейс отклоняется.
2. **Высокий:** ИИ влияет на решения, затрагивающие права или условия для клиента (одобрение, ставка, отказ), или автономно действует в отношении клиентов.
3. **Ограниченный:** ИИ напрямую взаимодействует с клиентами или выполняет действия через инструменты.
4. **Минимальный:** внутренний помощник, решение за сотрудником.

**Блокеры** не зависят от класса риска: персональные или конфиденциальные данные во внешнем зарубежном сервисе.

## 3. Требования по функциям NIST AI RMF

- **Govern:** владелец кейса, реестр ИИ-решений, согласование высокорисковых кейсов с ИБ, юристами и комплаенсом.
- **Map:** оценка обработки ПДн, маскирование, разграничение доступа, договор с облачным провайдером.
- **Measure:** набор проверок качества, тестирование на инъекции промпта, проверка на смещения для высокого риска.
- **Manage:** журналирование, информирование клиента, права инструментов агента, подтверждение человеком, мониторинг потребления ресурсов.

## 4. Приоритет

```
ценность      = 0..5 по чистому эффекту в месяц (логарифмическая шкала: 10 тыс. руб. = 1, 1 млн руб. = 5)
реализуемость = (готовность данных + простота интеграции) / 2, шкала 1..5
приоритет     = 0,6 × ценность + 0,4 × реализуемость − штраф за риск
штраф         = минимальный 0; ограниченный 0,5; высокий 1,5; недопустимый 5
```

## 5. Рекомендация (правила применяются по порядку)

1. Есть блокер → «Отклонить до устранения блокеров».
2. Эксплуатация дороже эффекта или окупаемость больше 24 месяцев → «Не окупается».
3. Высокий риск → «Пилот с контролем человека».
4. Реализуемость ниже 2,5 → «Подготовить данные и интеграции».
5. Окупаемость до 6 месяцев и приоритет от 3 → «Внедрять в первую очередь».
6. Иначе → «Пилот».

Очередь: сначала кейсы, которые можно внедрять, внутри группы по убыванию приоритета; отклонённые и неокупаемые в конце.

## 6. Жизненный цикл оценки

1. Первичная оценка по заявке (допущения видны в отчёте).
2. Пилот с фиксированными критериями успеха.
3. Пересчёт по фактическим данным пилота: реальная доля использования, минуты экономии, потребление токенов.
4. Решение о промышленной эксплуатации и повторная оценка раз в квартал.
